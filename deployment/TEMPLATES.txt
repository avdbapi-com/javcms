Website templates (themes)

Choose a theme in Admin > Site & theme > Themes ("Use this theme"), or in
Site & theme > Site identity (Themes card) and save. The list shows each theme's
display name from its info.ini, for example "Velvet (velvet)". New installs
start with JAVCMS Modern (javcms-modern). More help: docs/THEMES.md.

When is a theme selectable?

A folder template/<name>/ appears in the list when:
1. it contains info.ini and html/index/index.html;
2. info.ini does not say status = draft (themes still being built use draft);
3. the automatic safety scan finds no server-side files (.php, .phtml, .phar,
   .cgi, .sh, .exe, .htaccess, .user.ini, web.config, double extensions such as
   logo.php.jpg, images that contain <?php, or symlinks) and no dangerous PHP in
   its templates ({php} blocks, <?php blocks and template tags). The scan blocks:
   - eval, assert, create_function and the system/exec/shell_exec/passthru/
     popen/proc_open family;
   - file and directory writes (file_put_contents, fopen/fwrite, unlink, rmdir,
     copy, rename, mkdir, move_uploaded_file, symlink, chmod) and the CMS's own
     file/network helpers (mac_write_file, mac_arr2file, mac_mkdirss, mac_rmdirs,
     mac_read_file, mac_curl_get/post);
   - include/require of a file, {include} of a non-template path, and backticks;
   - a value read from $_GET/$_POST/... used as a function name, and any call
     through a variable the theme never binds to a closure (so $f='sys'.'tem';
     $f(...) is caught), new $var, and forward_static_call/iterator_apply;
   - a callback function (array_map, array_filter, usort, preg_replace_callback,
     ...) whose callback is a built-up string or names a blocked function, and
     the {$x|array_map=...} filter form;
   - reflection (Reflection*, Closure::fromCallable), raw SQL (Db::execute/query,
     ->execute/->query), reads of the database config (config('database...'),
     $Think.config.database, getenv), a decoder feeding a dynamic call, and
     preg_replace with the /e modifier.
The scan result is cached in runtime/theme-gate/ and is refreshed when a file
of the theme changes. Themes that are not selectable are listed under the
selector with the reason.

Names listed in deployment/reviewed-themes.json are always selectable
(operator allow-list). Add a theme there only after reviewing it yourself.

Install a new theme: copy its folder into template/, check that it appears in
Admin > Site & theme > Themes, select it and save. Saving a different
template applies through the current configuration/cache revision system; API
routes and saved import settings are unaffected.

Preview a theme for your browser only (other visitors keep the active theme):
click "Preview" next to the theme in Admin > Site & theme > Themes ("Stop
preview" ends it). Without the admin, run
"php tools/theme-preview-cookie.php <folder>" on the server and set the
printed value as the cookie jv_theme_preview for your site.
